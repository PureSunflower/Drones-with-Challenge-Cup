# 五枢雁阵 · 总方案规划

> 版本 v1.1 · 2026-11-25
>
> 本文档是全部设计的总汇，供核查。分项文档见 1/2/3 号文件。

---

## 第一部分：总体

### 1.1 一句话

五个可互相替代的节点（固定翼 1、旋翼 3、地面小车 1），在无单一中枢指挥的前提下，完成一次「搜索—确认—处置」闭环。

### 1.2 六实体

| 编号 | 平台 | 能力 | 任务 | 通信 |
| --- | --- | --- | --- | --- |
| N1 | 固定翼 | 远 | 广域搜索 | E34 + E32 |
| N2 | 旋翼·挂载 | 送 | 200 g 投送 | E34 + E32 |
| N3 | 旋翼·观察 | 清 | 抵近确认 | E34 + E32 |
| N4 | 旋翼·中继 | 通 | 链路延伸 | E34 + E32 |
| N5 | 地面小车 | 到 | 末端处置 | E34 + E32 |
| H | 母巢 | — | 起降充电装配 + 人工超控 | 收遥测 + 超控下发 |

### 1.3 设计原则（四条）

- **分层。** 感知 / 通信 / 任务 / 执行四层，每层只对接相邻层。
- **冗余。** 关键链路都有备份：通信双频段、任务可重认领、节点可替换。
- **收敛。** 出问题先收拢（返巢、确认），再行动。
- **减法。** 明确列出不做什么，比列做什么更重要。

### 1.4 实施优先级（重要）

三样东西的重要性差一个量级：

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| P0 | 通信链路与协议 | 不通，整个系统不存在 |
| P1 | 平台（飞起来的东西） | 可以买、可以借、可以简化 |
| P2 | 视觉、载荷、闭环 | 加分项 |

结论：先把通信做透，平台能飞就行，不追求性能。

### 1.5 平台获取策略（三选一）

| 路线 | 做法 | 成本 | 周期 | 风险 |
| --- | --- | --- | --- | --- |
| A 自建 | 买机架电机自己装 | 低 | 长 | 装配问题多 |
| B 半成品 | 买整机 + 改装通信 | 中 | 中 | 拆机风险 |
| C 成品 | 买能飞的，只做通信外挂 | 高 | 短 | 不能改飞控 |

决策规则：通信两个月内跑通，就按 A 做；跑不通，立刻转 C。

不为了「自己做」而自己做。

## 第二部分：任务链

### 2.1 三段

| 段 | 执行者 | 输入 | 输出 | 耗时 |
| --- | --- | --- | --- | --- |
| 搜索 | N1 | 航线 | 目标坐标 | 40–60 s |
| 确认 | N3 | 目标坐标 | 图像 + 确认 | 15–25 s |
| 处置 | N5 | 确认坐标 | 到达 / 投送 | 20–40 s |

N2（挂载）与 N4（中继）按需插入，不占主线。

### 2.2 触发条件

搜索段由「起飞进入航线」触发；确认段由「收到 TARGET」触发；处置段由「收到确认结果」触发。

全程无中心下发指令，任一节点均可发起 TARGET。

## 第三部分：通信（核心）

v1 只做 3.1–3.7：拓扑、双链路、帧格式、消息类型、状态机、认领、失联收敛。

3.8 与 3.9 是 v2 的事，写在这里是为了说明「想过」，不进入第一版实现。

### 3.1 拓扑

五个节点两两直连（全互联），任一点掉线不影响其余；超出视距靠多跳兜底，TTL 初始 3。

母巢不参与路由，只做后勤。

### 3.2 双链路

| 链路 | 模块 | 频段 | 距离 | 延迟 | 角色 |
| --- | --- | --- | --- | --- | --- |
| 近场 | E34-2G4M20D | 2.4G 硬件跳频 | 500 m | 10–20 ms | 协同主链路 |
| 远场 | E32-915M20D | 915M LoRa | 3–5 km | 100 ms+ | 冗余与回传 |

五个节点全部同时配两条，不做选配。

关键报文（心跳、目标坐标）同时走两条；接收端按（src, seq）去重。

### 3.3 帧格式（16 字节）

| 偏移 | 字段 | 长度 | 说明 |
| --- | --- | --- | --- |
| 0 | src | 1 | 源 ID |
| 1 | type | 1 | 消息类型 |
| 2–3 | seq | 2 | 序号（小端，可回绕） |
| 4–7 | lat | 4 | 纬度 ×1e7 |
| 8–11 | lon | 4 | 经度 ×1e7 |
| 12–13 | alt | 2 | 高度（分米） |
| 14 | status | 1 | 电量 4 bit + 阶段 4 bit |
| 15 | ttl | 1 | 剩余跳数 |

### 3.4 消息类型

| 值 | 名称 | 周期 | 说明 |
| --- | --- | --- | --- |
| 0x01 | HEARTBEAT | 1 Hz | 存活 |
| 0x02 | POSITION | 5 Hz | 位置 |
| 0x03 | TARGET | 事件 | 目标广播 |
| 0x04 | CLAIM | 事件 | 任务认领 |
| 0x05 | STATUS | 事件 | 故障 / 返航 |
| 0x06 | TEXT | 调试 | 日志 |
| 0x07 | CONTROL | 事件 | 人工超控（指定 ID） |
| 0x08 | REQUEST | 事件 | 关键动作请求授权 |
| 0x09 | GRANT | 事件 | 母巢批准 / 拒绝 |

### 3.5 状态机

- **邻居**：未知 →（收心跳）→ 在线 →（3 s 无）→ 疑似离线 →（10 s 无）→ 删除。
- **任务**：空闲 →（收 TARGET）→ 评估 →（评分最高）→ 认领 →（60 s 无进展）→ 空闲。

### 3.6 认领评分

```
score = 0.6 * 距离归一 + 0.3 * (1 - 电量) + 0.1 * 能力匹配
```

评分最高者延迟 200 ms 发 CLAIM，收到他人 CLAIM 即放弃。

### 3.7 失联收敛

任一节点失联，其余不散开搜索，先返巢确认电量与状态，再重新编组外出。

理由：未知情况下分散搜索，风险成倍。

### 3.8 人工超控（母巢 → 指定节点）【v2，远期】

**目的**：演示现场出问题时，人能立刻接管，避免撞机或摔机。

**帧**：type = 0x07，src = 母巢，ttl = 1（只一跳，不转发）。

**字段复用**：

- lat/lon 位置 → 前 4 字节存「目标节点 ID + 动作码」
- alt → 参数量（如速度档位）
- status → 保留

**动作码**：

| 码 | 动作 | 参数 |
| --- | --- | --- |
| 0x01 | 前进 | 速度档 1–3 |
| 0x02 | 后退 | 同 |
| 0x03 | 左转 | 角度 |
| 0x04 | 右转 | 角度 |
| 0x05 | 云台俯仰 | 角度 |
| 0x06 | 拍照 | — |
| 0x07 | 返航 | — |
| 0x08 | 切回自主 | — |

**模式优先级**：

手动模式 > 自主模式

- 收到 CONTROL（目标是自己）→ 切手动，计时器清零
- 每 200 ms 未收到新 CONTROL → 计时器 +1
- 5 s 无新指令 → 自动回自主模式

**5 秒超时不可省。** 否则电脑一死、串口一断，节点就僵在原地。

**安全约束**：

- 母巢发出的 CONTROL 必须 ttl = 1，不允许转发（防止他人接管）
- 只认 src = 0x31（母巢）的 CONTROL
- 手动模式下，避障与低电保护仍然生效

### 3.9 关键动作审批（一种安全限制）【v2，远期】

**原则**：日常协同去中心化，关键动作集中审批。

| 动作 | 是否需审批 |
| --- | --- |
| 移动、拍摄、跟随 | 否（自主执行） |
| 返航 | 是 |
| 投送（释放载荷） | 是 |
| 进入指定区域 | 是 |
| 人工超控接管 | 是 |

**流程**：

```
节点发起 REQUEST（动作码）
  → 母巢回 GRANT（同意 / 拒绝）
  → 同意则执行；拒绝则放弃
  → 10 s 无回复 → 默认执行
```

**三套计时器（不可混用）**：

| 计时器 | 时长 | 触发后 | 含义 |
| --- | --- | --- | --- |
| 授权等待 | 10 s | 默认执行 | 链路在，只是没人回复 |
| 链路心跳 | 20 s | 自动返航 | 彻底失联，联系不上 |
| 超控保持 | 5 s | 回自主模式 | 手动指令中断 |

**10 s 与 20 s 的区别要说清**：

- 10 s：心跳正常，母巢沉默 → 自己判断、自己干（不能因为没人回就不干活）
- 20 s：心跳也断了 → 不是「没人回」，是「联系不上」→ 回家

**为什么保留「默认执行」**：如果母巢一失联所有节点就停摆，那「去中心化」就是一句空话。默认执行是去中心化的底线。

**为什么又要「20 s 返航」**：默认执行可以，但不能无限制地盲干。20 秒是「再干一会儿」的窗，不是「永远自己飞」。

## 第四部分：平台要求（指标型，不锁型号）

### 4.1 通用电气要求

| 项 | 要求 |
| --- | --- |
| 主控 | STM32F407（主）+ ESP32-S3（通信协处理） |
| 通信 | E34-2G4 + E32-915 各一 |
| 供电 | 2S/3S 锂电，XT30 |
| 稳压 | 5 V / 3.3 V 两级，纹波 < 50 mV |
| 舵机电源 | 独立 5 V 分路 |
| 接口 | UART×2、I2C×1、PWM×6 |

### 4.2 各节点指标（只定指标，型号后定）

| 节点 | 翼展/轴距 | 全重 | 续航 | 载荷 | 必须满足 |
| --- | --- | --- | --- | --- | --- |
| N1 固定翼 | 700–900 mm | ≤ 500 g | ≥ 8 min | ≥ 100 g | 能按航线飞、能抛飞 |
| N2 旋翼挂载 | 200–300 mm | ≤ 800 g | ≥ 8 min | ≥ 200 g | 能悬停 60 s 不飘 |
| N3 旋翼观察 | 200–300 mm | ≤ 700 g | ≥ 8 min | ≥ 100 g | 能定点悬停 |
| N4 旋翼中继 | 200–300 mm | ≤ 650 g | ≥ 10 min | —— | 天线可外延 |
| N5 小车 | —— | ≤ 2 kg | ≥ 30 min | ≥ 300 g | 能自主直行 + 转向 |

以上是「够用」的门槛，不是「最优」。达标即可，不追求余量。

### 4.3 指标怎么用

采购或自建时把这张表当验收单：达不到就换，达到了就不再讨论。

**别在平台上纠结超过三周。** 三周内没定，直接买成品。

### 4.4 结构要点（仅自建固定翼时适用）

一体化翼面（主梁 3×5 桐木 + 翼肋 + 牛皮纸蒙皮），机身吊舱式悬挂。

旋翼载荷位：4×M3（30×30 mm）+ 5V/12V/UART。

## 第五部分：软件

### 5.1 模块划分

| 模块 | 职责 |
| --- | --- |
| frame | 组帧、解帧、校验 |
| link_e34 | E34 驱动（串口 + 配置） |
| link_e32 | E32 驱动 |
| neighbor | 邻居表、心跳超时 |
| route | 多跳转发、去重 |

### 5.2 开发顺序

先用 ESP32 跑通协议（帧、邻居、认领），再换 E34/E32。协议层不动，只换发送函数。

## 第九部分：风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 2.4G 现场干扰 | 掉包、失联 | 硬件跳频 + 双频段 + 天线外置 |
| 定位精度 | 坐标对不上 | GPS 粗定位 + 视觉/UWB 精定位 |
| 飞行事故 | 人员受伤、项目终止 | 空旷场地、限高 50 m、目视 |
| 进度延误 | 结题困难 | 每阶段最小可交付，宁可缩范围 |
| 单人承担 | 工作量超载 | 三节点起步，先不追求五节点 |
| 平台做不出来 | 无法演示 | 三周一过，直接买成品 |

## 第十部分：明确不做

1. 自主避障（激光雷达 + 实时规划，超范围）
2. 集群编队与气动节能（本科做不出可信结果）
3. 大模型机上决策（算力/延迟/功耗不满足）
4. 自动路由算法（TTL 泛洪足够 5 节点）
5. 通信加密（演示场景，增加延迟与调试难度）

---

**核查要点**：数字一致性（重量、预算、延迟）、模块型号、阶段判据、不做清单。
